# Prompteur H2 Managed-Agent Pilot — 2026-09-21

## Decision

The `managed-coding-agent` profile remains **experimental**. The deterministic comparison substrate is healthy, but this run did not produce trustworthy downstream task-output artifacts from the Antigravity worker, so there is not enough evidence to promote, auto-select, or claim that the profile improves task quality.

## What was verified first

- `npm run check` passes locally.
- The paired-evaluation contract is currently schema `1.3`.
- Schema `1.3` supports an optional explicit deterministic candidate arm while preserving the ordinary baseline.
- The candidate arm cannot label itself improved: downstream execution remains `not_run`, task quality remains `not_evaluated`, and `mayLabelImproved` remains `false`.
- The managed profile remains explicit-only and removes exactly the redundant generic instruction `Inspect the available context and tools before changing anything.` while retaining minimal-implementation, non-fabrication, and verification guidance.

## Pilot task

A self-contained JavaScript task was selected to make grading objective: replace a `unique` implementation that string-coerces values with one that preserves original types, first-occurrence order, and `NaN` deduplication. The same task was prepared in three arms:

1. Raw user request.
2. Ordinary deterministic Prompteur agent baseline.
3. Deterministic baseline with the explicit `managed-coding-agent` profile.

The baseline and profiled prompts were generated by the real Prompteur CLI. The profiled prompt differed only by the one profile-approved suppression.

## Downstream execution outcome

Three isolated Antigravity/Gemini 3.8 Flash Medium tasks were launched, one per arm. The first attempt used an incompatible model/effort pair and was rejected before execution; it was corrected to `gemini-3.8-flash-medium` with medium effort.

The corrected tasks completed, but the benchmark worker did **not** materialize the requested output files. Each arm was revised once with an even narrower instruction to create exactly its requested artifact and nothing else. The raw arm still produced no artifact. A separate artifact-path diagnostic using a normal `artifacts/h2/...` path also produced no artifact, ruling out `.ai-bridge` as the cause.

Because the task-result interface did not expose the model's raw answer separately, inventing or reconstructing an output would invalidate the experiment. The worker token/duration figures are also not suitable as efficiency evidence: the harness injects different repository/task-envelope context, so those totals are not controlled measurements of prompt length alone.

## Bounded hardening completed in this run

The existing schema-1.3 candidate-arm code was present but lacked direct tests and README documentation. This run added focused coverage proving that:

- an explicit candidate profile is recorded without changing the baseline arm;
- candidate execution remains `not_run` and cannot claim quality improvement;
- the managed candidate is shorter only because of its approved suppression;
- the baseline still contains the suppressed instruction;
- no candidate arm appears by default.

`evaluations/README.md` now documents the schema-1.3 Raw/Baseline/Candidate boundary.

## Verification

- `node --test tests/paired-evaluation.test.js`: **14/14 passed**.
- `npm run check`: **44 passed, 0 failed, 1 expected Windows symlink-permission skip**.
- Deterministic evaluation: **6/6 passed**.

## Next evidence gate

Do not build an autonomous optimizer and do not promote the managed profile yet. The next useful step is to obtain a downstream execution lane that returns a verifiable output payload or artifact per arm, then run multiple representative tasks with the same model/harness and grade functional success, safety/constraint adherence, latency, and controlled prompt-token cost. Until that exists, Prompteur's ordinary deterministic compiler remains the default and the profile remains explicitly experimental.
